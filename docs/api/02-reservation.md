## 예약 슬롯 규칙

이 파일의 여러 API가 같은 규칙으로 "예약할 수 있는 칸"을 셉니다.

- **칸**: 진료일정 하나의 요일에, 시작시각부터 예약간격분마다 종료시각 전까지 생기는 시각입니다. 예: 수 09:00~12:00, 30분 → 09:00, 09:30, …, 11:30
- **빈 칸**: 그 날짜에 그 일정의 휴진이 없고, 그 일정·그 일시에 '취소'가 아닌 예약이 없는 칸입니다.
- **예약 가능한 시각**: 지금보다 뒤이고, 그 진료과 의사들의 일정 중 그 시각에 빈 칸이 하나라도 있는 시각입니다. 환자는 의사를 고르지 않습니다.

## 다른 담당자가 쓰는 기능

HTTP API가 아니라 백엔드 안에서 부르는 기능입니다.

| 기능 | 부르는 쪽 | 하는 일 |
| --- | --- | --- |
| 진료용 예약 확인 | 박지수 (3-1 외래) | 예약번호로 환자번호, 상태, 일정번호, 배정된 의사를 돌려줌 (2-6과 같은 내용) |
| 예약 완료 처리 | 박지수 (3-1 외래) | 예약을 '예약' → '완료'로 바꿈. 진료 저장과 같은 트랜잭션 안에서 실행해, 진료 저장이 실패하면 예약도 '예약'으로 남게 함 |

## 2-1. 예약 가능한 날짜

| 항목 | 내용 |
| --- | --- |
| 요청 | `GET /api/booking/dates?departmentCode=IM&month=2026-11` |
| 권한 | 환자 |
| 화면 | P2 예약하기 달력, P3a 시간 변경 |
| 순위 | 1 |

한 달의 날짜마다 그 진료과에 예약 가능한 시각이 있는지 돌려줍니다. P2는 가능한 날이 없는 날을 회색으로 끄고, 고른 날에 시간이 0개면 다음 가능한 날로 이동합니다.

**쿼리**

| 이름 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `departmentCode` | string | O | 진료과코드 |
| `month` | string | O | `YYYY-MM` |

**응답 `200 OK`**: 그 달의 모든 날짜가 날짜순으로 들어 있습니다.

```json
[
  { "date": "2026-11-10", "available": false },
  { "date": "2026-11-11", "available": true },
  { "date": "2026-11-12", "available": true }
]
```

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| `date` | date | 날짜 |
| `available` | boolean | [예약 가능한 시각](#예약-슬롯-규칙)이 하나라도 있으면 true. 지난 날짜는 false |

**오류**

| 상태 | code | 언제 |
| --- | --- | --- |
| 400 | `VALIDATION_FAILED` | 쿼리가 없거나 `month` 형식이 틀림 |
| 401, 403 | | 공통 (의료진이 호출하면 403) |
| 404 | `NOT_FOUND` | 없는 진료과코드 |

## 2-2. 예약 가능한 시간

| 항목 | 내용 |
| --- | --- |
| 요청 | `GET /api/booking/slots?departmentCode=IM&date=2026-11-11` |
| 권한 | 환자 |
| 화면 | P2 예약하기 시간 칸, P3a 시간 변경 |
| 순위 | 1 |

고른 진료과·날짜의 시간 칸을 돌려줍니다. 의사 정보는 주지 않습니다(의사를 고르는 단계 없음).

**쿼리**

| 이름 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `departmentCode` | string | O | 진료과코드 |
| `date` | date | O | 날짜 |

**응답 `200 OK`**: 시각순

```json
[
  { "time": "09:00:00", "available": false, "mine": false },
  { "time": "09:30:00", "available": true, "mine": false },
  { "time": "10:00:00", "available": true, "mine": false },
  { "time": "10:30:00", "available": false, "mine": true }
]
```

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| `time` | time | 시각. 그날 그 진료과 일정들의 [칸](#예약-슬롯-규칙)을 모두 합친 것. 휴진인 일정의 칸도 들어 있음 |
| `available` | boolean | 예약할 수 있으면 true. 모든 의사가 차 있거나 쉬거나 이미 지난 시각이면 false |
| `mine` | boolean | 로그인한 환자가 그 일시에 다른 예약(다른 진료과 포함)을 이미 가지고 있음. P2는 "내 예약 있음"으로 표시하고 누르지 못하게 함 |

**오류**: 2-1과 같습니다.

**규칙**

- 휴진은 화면에 직접 나오지 않습니다. 의사 일부가 쉬면 남은 의사로 배정되고, 모두 쉬면 그 시각이 꺼집니다.
- 한 환자는 같은 일시에 예약 1건만 가집니다(예약의 함수형 UNIQUE). 그래서 `mine` 칸은 고를 수 없습니다.

## 2-3. 예약하기

| 항목 | 내용 |
| --- | --- |
| 요청 | `POST /api/me/reservations` |
| 권한 | 환자 |
| 화면 | P2 예약하기 |
| 순위 | 1 |

환자가 진료과·일시를 고르면, 서버가 그 시각에 빈 일정 중 하나를 무작위로 골라 예약을 만듭니다.

**요청 본문**

| 필드 | 타입 | 필수 | 규칙 |
| --- | --- | --- | --- |
| `departmentCode` | string | O | 진료과코드 |
| `appointmentAt` | datetime | O | 지금보다 뒤이고, 그 진료과 일정의 칸에 맞는 시각 |
| `symptomNote` | string \| null | | 500자 이내. 비워도 됨 |

```json
{
  "departmentCode": "IM",
  "appointmentAt": "2026-11-11T10:00:00",
  "symptomNote": "식후 속쓰림이 일주일째"
}
```

**응답 `201 Created`**: [내 예약 객체](#내-예약-객체). P3는 "담당 의사는 박지훈입니다"처럼 배정된 의사를 바로 알려 줍니다.

**오류**

| 상태 | code | 언제 |
| --- | --- | --- |
| 400 | `VALIDATION_FAILED` | 지난 시각, 그 진료과 어느 일정의 칸에도 맞지 않는 시각, 증상메모가 500자를 넘음 |
| 401, 403 | | 공통 |
| 404 | `NOT_FOUND` | 없는 진료과코드 |
| 409 | `SLOT_TAKEN` | 그 시각의 빈 일정이 모두 찼음. P2는 시간표를 새로 받아 그 칸을 끔 |
| 409 | `PATIENT_TIME_CONFLICT` | 같은 일시에 이 환자의 다른 예약이 있음 |

**규칙**

- 예약일시는 배정된 진료일정의 요일, 시작시각 이상 종료시각 미만, 예약간격 단위여야 합니다.
- 진료과 → 의료진 → 진료일정에서 요일·시간이 맞고, 그날 휴진이 아니며, 그 시각에 예약이 없는 일정을 무작위로 골라 저장합니다.
- 함수형 UNIQUE 두 개: 같은 일정·같은 일시에 취소 아닌 예약 1건, 한 환자는 같은 일시에 예약 1건
- 예약상태는 '예약', 등록일시는 저장한 시각입니다.

**백엔드 메모**

- 처리 순서: (환자, 일시) 중복 확인 → 빈 일정 후보를 모아 섞기 → 하나씩 INSERT 시도
- 동시에 같은 칸을 잡으려 하면 (일정, 일시) UNIQUE 위반이 납니다. 위반이 나면 다음 후보로 다시 시도하고, 후보가 다 떨어지면 `SLOT_TAKEN`을 돌려줍니다. 업무분담서 완료 기준: 마지막 한 자리에 동시 요청 → 한 건만 성공
- (환자, 일시) UNIQUE 위반이 나면 `PATIENT_TIME_CONFLICT`입니다. 어느 인덱스에서 났는지는 제약 이름으로 구분합니다.

## 2-4. 내 예약 목록

로그인한 환자의 예약을 모든 상태로 돌려줍니다. 프론트엔드가 예정(지금 이후 '예약')과 지난 예약으로 나눕니다.

## 2-5. 오늘 진료 목록

| 항목 | 내용 |
| --- | --- |
| 요청 | `GET /api/reservations?date=2026-11-11` |
| 권한 | 의사·간호사 |
| 화면 | S1 오늘 진료, S9 간호사가 보는 오늘 진료 |
| 순위 | 1 |

한 날짜의 예약과 그날의 휴진을 함께 돌려줍니다. 화면 요약이 필요해서 객체로 감쌉니다.

- 의사: 본인 진료일정에 배정된 예약만
- 간호사: 본인 진료과 의사 전체의 예약 (S9은 담당의 컬럼을 붙임)

**쿼리**

| 이름 | 타입 | 필수 | 설명 |

**응답 `200 OK`**

      "reservationId": 1201,
      "appointmentAt": "2026-11-11T10:00:00",
      "status": "예약",

**오류**: 400(날짜 형식), 401, 403(환자·원무가 호출)

**규칙**

- 예약에는 의사번호가 없습니다. 예약 → 진료일정 → 의료진으로 의사와 진료과를 찾습니다.

## 2-16. 휴진 등록

| 항목 | 내용 |
| --- | --- |
| 요청 | `POST /api/day-offs` |
| 권한 | 의사·간호사 |
| 화면 | S7a 휴진 등록 |
| 순위 | 3 |

휴진 행을 만들고, 그날 그 일정의 '예약' 상태 예약을 같은 진료과·같은 시각의 빈 일정으로 옮깁니다. 옮길 곳이 없으면 취소합니다. 모두 한 트랜잭션입니다.

**요청 본문**

| 필드 | 타입 | 필수 | 규칙 |
| --- | --- | --- | --- |
| `scheduleIds` | number[] | O | 1개 이상, 같은 의사·같은 요일의 일정. "종일"이면 그날 일정 전부 |
| `offDate` | date | O | 오늘보다 뒤, 요일이 일정 요일과 같음 |
| `reason` | string \| null | | 200자 이내. 비워도 됨 |

```json
{ "scheduleIds": [14], "offDate": "2026-11-18", "reason": "학회" }
```

**응답 `201 Created`**

```json
{
  "dayOffs": [
    { "dayOffId": 81, "scheduleId": 14, "offDate": "2026-11-18", "reason": "학회", "doctorId": 12, "dayOfWeek": "수", "startTime": "09:00:00", "endTime": "12:00:00" }
  ],
  "reassigned": [],
  "cancelled": []
}
```

`reassigned`, `cancelled`는 2-15와 같은 모양이고, 실제로 바뀐 결과입니다.

**오류**

| 상태 | code | 언제 |
| --- | --- | --- |
| 400 | `VALIDATION_FAILED` | 2-15와 같음, `scheduleIds`가 비어 있음, 사유가 200자를 넘음 |
| 401, 403 | | 공통 |
| 404 | `NOT_FOUND` | 없는 일정번호 |
| 409 | `DAY_OFF_EXISTS` | 같은 일정·같은 날짜에 휴진이 이미 있음. `details`에 `{ "scheduleId": 14, "dayOffId": 77 }` |

**규칙**

- 휴진일의 요일은 진료일정.요일과 같아야 합니다. (CHECK로는 막을 수 없어 앱에서 검사)
- UNIQUE (일정번호, 휴진일)
- 재배정은 예약의 일정번호만 바꾸고 일시는 그대로 둡니다. 환자 화면에는 새 담당의만 보입니다.
- 사유는 의료진 화면(S1, S7)에만 보이고 환자에게는 보이지 않습니다.
- 업무분담서 완료 기준: 재배정되는 경우와 취소되는 경우를 모두 확인합니다.

**백엔드 메모**

- 영향받는 예약을 예약일시 순으로 하나씩 처리합니다. 후보 일정은 같은 진료과·같은 요일이고, 이번에 쉬는 일정이 아니며, 그날 휴진이 없고, 그 시각이 칸에 맞고, 그 시각에 취소 아닌 예약이 없는 일정입니다. 앞에서 옮긴 예약도 자리를 차지한 것으로 셉니다.
- 후보가 여럿이면 **일정번호가 가장 작은 것**을 고릅니다. 무작위로 고르면 2-15 미리 보기와 실제 결과가 달라질 수 있기 때문입니다.

## 2-17. 휴진 취소

| 항목 | 내용 |
| --- | --- |
| 요청 | `DELETE /api/day-offs/{dayOffId}` |
| 권한 | 의사·간호사 |
| 화면 | S7b 휴진 취소 |
| 순위 | 3 |

**응답 `204 No Content`**

**오류**: 401, 403, 404, 409 `INVALID_STATUS`(휴진일이 오늘이거나 지났음)

**규칙**

- 앞으로의 휴진만 취소할 수 있습니다. 지난 휴진은 기록으로 남깁니다.
- 취소해도 이미 옮겨지거나 취소된 예약은 돌아오지 않습니다. 화면의 확인 대화상자에 이 점을 적습니다.
