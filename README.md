## 사용자 구분

- **환자:** 등록된 환자 정보를 바탕으로 온라인 회원가입을 하고, 본인의 예약과 진료 관련 정보를 조회합니다. 검사 결과는 완료된 건을 대상으로 조회합니다.
- **의료진:** 의사와 간호사를 의료진 테이블에서 관리합니다. 환자·예약 등 공통 관리 업무를 수행하며, 진료·진단·처방 작성은 의사에게 한정합니다.

환자 계정과 의료진 계정을 구분하며, 비밀번호는 해시값으로 저장합니다. 별도 관리자 계정은 두지 않고, 의료진 계정은 기존 의료진이 등록하는 방식으로 설계합니다.

## 핵심 설계

### 1. 진료과와 시간을 선택하는 예약

환자는 **진료과·날짜·시간을 선택**하고, 시스템은 해당 조건에 예약 가능한 의사의 진료일정을 찾아 자동 배정합니다. 환자가 의사를 직접 선택하는 방식은 아닙니다.

데이터 관계는 다음과 같습니다.

```text
진료과 → 의료진 → 진료일정 → 예약 ← 환자
                       └→ 휴진
```

- 진료일정은 의사별로 반복되는 주간 일정입니다.
- 휴진은 특정 일정과 날짜를 조합하여 등록합니다. 동일한 일정·날짜의 중복 휴진은 허용하지 않습니다.
- 예약 시 요일, 진료시간, 예약 간격, 휴진 여부와 기존 예약을 확인합니다.
- 취소되지 않은 예약끼리는 같은 일정·시간의 중복 예약 및 같은 환자의 동일 시각 중복 예약을 제한합니다.
- 휴진 등록으로 기존 예약을 유지할 수 없으면 같은 진료과·시간의 가능한 일정으로 재배정하고, 대체 일정이 없으면 취소합니다.

### 2. 외래와 입원 중 진료를 하나의 진료 테이블로 관리

외래 진료와 회진은 모두 진료 기록이므로 같은 테이블에 저장합니다. 진료구분과 연결된 외래키로 상황을 구분합니다.

| 구분 | 예약번호 | 입원번호 | 의미 |
| --- | --- | --- | --- |
| 외래 진료 | 필수 | NULL | 예약을 통해 받은 외래 진료 |
| 입원 중 진료 | NULL | 필수 | 특정 입원 기간 중 받은 회진 등의 진료 |

예약번호와 입원번호는 **정확히 하나만 존재**해야 하며, 진료구분도 이에 맞아야 합니다. 입원 중 진료마다 새로운 진료번호를 발급하되 같은 입원번호로 연결합니다.

입원을 결정한 최초 외래 진료는 외래 기록으로 유지합니다. 해당 행의 입원번호를 채우는 대신, **입원 테이블의 입원결정진료번호**가 최초 진료를 참조합니다.

```text
최초 외래 진료 ← 입원.입원결정진료번호
                    ↑
         입원 중 진료.입원번호
```

따라서 입원을 결정한 진료와 입원 중 발생한 여러 진료를 구별할 수 있습니다. 회진만을 위한 별도 기록 테이블은 두지 않습니다.

### 3. 퇴원 시 한 번에 청구

**진료 행이 추가된다고 결제 행이 자동으로 생기지는 않습니다.** 입원 중 진료는 비용을 집계하는 근거이며, 각 회진에 결제를 만들지 않습니다.

- 일반 외래는 해당 외래 진료를 기준으로 청구합니다.
- 입원으로 이어진 외래는 퇴원 후 입원 관련 비용까지 합산합니다.
- 이때 결제는 **입원을 결정한 최초 외래 진료번호**에 연결합니다.
- 결제 테이블에는 입원번호를 별도로 두지 않습니다. 입원결정진료번호 관계를 통해 해당 입원을 찾고, 입원번호로 입원 중 진료를 모읍니다.

업무분석서의 비용 기준을 적용하면 다음과 같습니다.

```text
일반 외래 청구액
  = 고정 진찰료 + 검사비 + 원내 약제비

입원 통합 청구액
  = 최초 외래 진찰료
  + 최초 외래 및 입원 중 진료의 검사비·원내 약제비
  + 입원료

입원료 = 병실의 1일 입원료 × 청구 일수
청구 일수 = 퇴원 날짜 - 입원 날짜 (최소 1일)

원내 약제비 = Σ(약품 단가 × 1회 투여량 × 일일 횟수 × 투약 일수)
```

회진에는 별도 고정 진찰료를 붙이지 않습니다. 검사비는 시행·완료된 검사를 대상으로 집계하고, 원외 처방 약제비는 병원 청구에서 제외합니다. 병실 이동은 현재 범위에서 다루지 않습니다.

청구 후 기준정보의 가격이 변경되어도 기존 청구금액은 유지합니다. 취소한 결제는 삭제하지 않고 보관하며, 재청구 시 새로운 결제 행을 생성합니다. 동일 진료에 대해 **취소되지 않은 결제는 최대 1건**만 허용합니다.

## 주요 무결성 규칙

| 대상 | 규칙 |
| --- | --- |
| 진료 | 예약번호·입원번호 중 정확히 하나만 존재하며 진료구분과 일치 |
| 진료 소견 | 필수 입력, 특별한 소견이 없으면 이를 명시 |
| 처방상세 | 동일 처방전 내 약품 중복 금지, 투여량·횟수·일수는 양수 |
| 검사 | 시행·완료 상태면 시행일시 필수, 완료 상태면 판정·판독소견·판독자 필수 |
| 검사 결과값 | 영상·기능검사 등을 고려하여 숫자 결과값은 NULL 허용 |
| 입원 | 입원 결정 진료당 최대 1건, 환자의 동시 입원과 병실 정원 초과 제한 |
| 입원 중 진료 | 입원 환자와 진료 환자가 일치하고 진료일시가 입원 기간 안에 존재 |
| 결제 | 완료·취소 상태면 결제수단·결제일시 필수 |
| 결제 이력 | 취소 이력 보존, 동일 진료에 취소되지 않은 결제는 최대 1건 |

규칙의 성격에 따라 PK·FK·UNIQUE·NOT NULL·CHECK와 애플리케이션 검증을 구분하여 적용합니다. 다른 행이나 테이블을 조회해야 하는 시간 중복·정원·환자 일치 검증은 단일 행 CHECK만으로 처리하지 않으며, 구현 시 트랜잭션과 동시성 제어도 함께 고려합니다.
