## 청구 금액 계산

결제를 만드는 순간 아래 산식으로 계산해 결제.청구비용에 저장합니다. 테이블정의서 결제 규칙과 같습니다.

| 구분 | 산식 |
| --- | --- |
| 외래 | 진찰료 + 검사비 + 약제비 |
| 입원 | 입원을 결정한 진료의 외래 금액 + 회진 진료의 검사비·약제비(진찰료 없음) + 입원비 |

| 항목 | 계산 |
| --- | --- |
| 진찰료 | 15,000원 고정 ([README 고정값](README.md#고정값)) |
| 검사비 | 그 진료에서 **요청한** 검사의 검사항목.검사비 합. 결제는 진료를 저장할 때 생기고 그때 검사는 아직 '요청' 상태이므로, 상태와 관계없이 요청한 검사를 모두 셉니다 |
| 약제비 | '원내' 처방의 처방상세마다 약품.단가 × 1회투여량 × 1일투여횟수 × 투약일수를 더한 값. '원외' 처방은 약국에서 따로 계산하므로 넣지 않음 |
| 입원비 | 병실.입원료 × 입원일수 |
| 입원일수 | 퇴원 날짜 − 입원 날짜 (날짜만 비교). 같은 날 퇴원하면 1일 |

- **반올림**: 1회투여량이 소수라 약제비만 소수가 나올 수 있습니다. 약제비를 모두 더한 뒤 원 단위로 **한 번만** 반올림합니다(0.5는 올림). 예: 472.5원짜리 두 줄은 합계 945원입니다. 줄마다 반올림하면 946원이 되어 틀립니다. 진찰료·검사비·입원비는 정수라 반올림하지 않습니다.
- **단가 시점**: 결제를 만드는 순간의 약품.단가, 검사항목.검사비, 병실.입원료로 계산합니다. 나중에 단가가 바뀌어도 저장된 청구비용은 그대로입니다.
- **항목별 금액은 저장하지 않습니다.** 화면(S6, P6)에는 합계와 [포함 내역](#결제-객체)만 보여 줍니다. 단가가 바뀐 뒤 항목 금액을 다시 계산하면 합계와 어긋나기 때문입니다.

**계산 예**

외래 (P6의 10. 28 내과 외래):

| 항목 | 금액 |
| --- | --- |
| 진찰료 | 15,000 |
| 검사비: 일반혈액검사 8,000 + CRP 15,500 | 23,500 |
| 약제비: 원외 처방만 있음 | 0 |
| **합계** | **38,500** |

입원 (이정민, 502호, 11. 05 입원 → 11. 11 퇴원):

| 항목 | 금액 |
| --- | --- |
| 결정 진료 진찰료 | 15,000 |
| 결정 진료 검사비: 흉부 X선 | 15,500 |
| 회진 검사비: 일반혈액검사 8,000 × 2 + 심전도 12,000 | 28,000 |
| 회진 약제비: 세프트리악손주 1g 4,200 × 1바이알 × 1일 2회 × 3일 | 25,200 |
| 입원비: 60,000 × 6일 | 360,000 |
| **합계** | **443,700** |

**백엔드 메모**

- 1회투여량이 DECIMAL(6,2)이므로 약제비는 `BigDecimal`로 더하고 마지막에 `setScale(0, RoundingMode.HALF_UP)` 합니다.
- 진료별 요청 검사와 원내 처방상세는 박지수님의 [청구 근거 조회 기능](03-encounter.md#다른-담당자가-쓰는-기능)으로 가져옵니다.

## 결제 객체

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| `paymentId` | number | 결제번호 |
| `encounterId` | number | 청구 대상 진료. 입원 청구면 입원을 결정한 외래 진료 |
| `billingType` | `'외래' \| '입원'` | 외래 청구인지, 퇴원 때 만든 입원 통합 청구인지 (결정 진료에 입원이 있으면 '입원') |
| `amount` | number | 청구비용(원) |
| `status` | `'미결제' \| '완료' \| '취소'` | 결제상태 |
| `method` | `'카드' \| '현금' \| '계좌이체'` \| null | 결제수단. '완료'·'취소'면 있음 |
| `createdAt` | datetime | 생성일시 |
| `paidAt` | datetime \| null | 결제일시. '완료'·'취소'면 있음 |
| `encounterAt` | datetime | 청구 대상 진료의 진료일시 |
| `departmentName` | string | 진료과명 |
| `admission` | object \| null | 입원 청구면 `{ admissionId, roomNo, admittedAt, dischargedAt }`. P6은 진료일 대신 "9. 01~9. 05 내과 입원"처럼 기간을 보여 줌 |
| `includes` | object | 포함 내역. 금액이 아니라 무엇이 들어갔는지만 |
| `includes.consultationCount` | number | 진찰 횟수 (외래·입원 모두 1) |
| `includes.examNames` | string[] | 청구에 들어간 검사 이름 |
| `includes.inHousePrescriptionCount` | number | 청구에 들어간 원내 처방전 수 |
| `includes.hasOutsidePrescription` | boolean | 원외 처방이 있음. 화면에 "원외 처방(약국 계산)" |
| `includes.roundCount` | number | 입원 청구에 합친 회진 수. 외래는 0 |
| `includes.admissionDays` | number \| null | 입원 청구의 입원일수. 외래는 null |

```json
{
  "paymentId": 9077,
  "encounterId": 5521,
  "billingType": "외래",
  "amount": 38500,
  "status": "미결제",
  "method": null,
  "createdAt": "2026-10-28T10:42:00",
  "paidAt": null,
  "encounterAt": "2026-10-28T09:35:00",
  "departmentName": "내과",
  "admission": null,
  "includes": {
    "consultationCount": 1,
    "examNames": ["일반혈액검사", "CRP"],
    "inHousePrescriptionCount": 0,
    "hasOutsidePrescription": true,
    "roundCount": 0,
    "admissionDays": null
  }
}
```

`includes`는 조회할 때 진료·검사·처방에서 다시 셉니다. 진료를 저장한 뒤에는 처방·검사를 고칠 수 없으므로([3-4](03-encounter.md#3-4-진료-기록-수정)) 청구 때와 같은 내용이 나옵니다.

## 6-1. 환자별 결제 목록

| 항목 | 내용 |
| --- | --- |
| 요청 | `GET /api/payments?patientId=10234` |
| 권한 | 원무 |
| 화면 | S6 수납 (미결제·완료 탭), S6b 결제 취소 |
| 순위 | 1 |

원무 직원이 환자번호로 조회한 환자의 결제를 모든 상태로 돌려줍니다. 환자 요약은 [1-6](01-member.md#1-6-환자-정보-의료진용)으로 따로 불러옵니다.

**쿼리**

| 이름 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `patientId` | number | O | 환자번호 |

**응답 `200 OK`**: [결제 객체](#결제-객체)의 배열, 생성일시 내림차순. 탭별 건수(미결제 2 · 완료 3)는 프론트엔드가 셉니다.

**오류**

| 상태 | code | 언제 |
| --- | --- | --- |
| 400 | `VALIDATION_FAILED` | `patientId`가 없음 |
| 401 | `UNAUTHENTICATED` | |
| 403 | `FORBIDDEN` | 원무가 아님 |
| 404 | `NOT_FOUND` | 없는 환자번호 |

**규칙**

- 결제에는 환자번호가 없습니다. 결제 → 진료.환자번호로 찾습니다.
- 회진 진료에는 결제가 없으므로 회진의 검사·처방은 입원 청구 1건에 합쳐져 보입니다.

## 6-2. 수납

| 항목 | 내용 |
| --- | --- |
| 요청 | `POST /api/payments/{paymentId}/pay` |
| 권한 | 원무 |
| 화면 | S6 수납 (오른쪽 패널의 "수납 완료") |
| 순위 | 1 |

'미결제' 결제를 '완료'로 바꿉니다. 결제일시는 누른 시각입니다. 금액은 고치지 않습니다.

**요청 본문**

| 필드 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `method` | `'카드' \| '현금' \| '계좌이체'` | O | 결제수단. 고르기 전에는 화면 버튼이 꺼져 있음 |

```json
{ "method": "카드" }
```

**응답 `200 OK`**: 바뀐 [결제 객체](#결제-객체)

**오류**

| 상태 | code | 언제 |
| --- | --- | --- |
| 400 | `VALIDATION_FAILED` | `method`가 없거나 다른 값 |
| 401 | `UNAUTHENTICATED` | |
| 403 | `FORBIDDEN` | 원무가 아님 |
| 404 | `NOT_FOUND` | 없는 결제번호 |
| 409 | `INVALID_STATUS` | 상태가 '미결제'가 아님 |

**규칙**

- 상태는 미결제 → 완료 → 취소 순서입니다. '완료'·'취소'로 바꾸는 일은 직종 '원무'만 합니다.
- CHECK 상태 = '미결제' OR (결제수단, 결제일시 NOT NULL)

## 6-3. 내 결제 내역

| 항목 | 내용 |
| --- | --- |
| 요청 | `GET /api/me/payments` |
| 권한 | 환자 |
| 화면 | P1 미결제 진료비 카드, P6 결제 내역 |
| 순위 | 1 |

로그인한 환자의 결제를 모든 상태로 돌려줍니다. 웹에서는 조회만 하고, 수납은 원무 창구에서 합니다.

**응답 `200 OK`**: [결제 객체](#결제-객체)의 배열, 생성일시 내림차순

- 취소한 결제도 보입니다. 같은 진료에 결제가 2건 보일 수 있으므로 P6은 취소 행에 "다시 청구되어 취소됨"을 적습니다.

**오류**: 401, 403(의료진이 호출)

## 6-4. 결제 취소

| 항목 | 내용 |
| --- | --- |
| 요청 | `POST /api/payments/{paymentId}/cancel` |
| 권한 | 원무 |
| 화면 | S6b 결제 취소 (수납 화면 완료 탭) |
| 순위 | 3 |

수납이 끝난('완료') 결제를 '취소'로 바꾸고, 같은 진료에 **지금 단가로 다시 계산한** '미결제' 결제를 새로 만듭니다. 한 트랜잭션입니다. 요청 본문은 없습니다.

**응답 `200 OK`**

```json
{
  "cancelled": {
    "paymentId": 9061,
    "encounterId": 5440,
    "billingType": "외래",
    "amount": 15000,
    "status": "취소",
    "method": "카드",
    "createdAt": "2026-11-11T09:30:00",
    "paidAt": "2026-11-11T09:48:00",
    "encounterAt": "2026-11-11T09:05:00",
    "departmentName": "내과",
    "admission": null,
    "includes": { "consultationCount": 1, "examNames": [], "inHousePrescriptionCount": 0, "hasOutsidePrescription": false, "roundCount": 0, "admissionDays": null }
  },
  "newPayment": {
    "paymentId": 9130,
    "encounterId": 5440,
    "billingType": "외래",
    "amount": 15000,
    "status": "미결제",
    "method": null,
    "createdAt": "2026-11-11T15:02:00",
    "paidAt": null,
    "encounterAt": "2026-11-11T09:05:00",
    "departmentName": "내과",
    "admission": null,
    "includes": { "consultationCount": 1, "examNames": [], "inHousePrescriptionCount": 0, "hasOutsidePrescription": false, "roundCount": 0, "admissionDays": null }
  }
}
```

**오류**

| 상태 | code | 언제 |
| --- | --- | --- |
| 401 | `UNAUTHENTICATED` | |
| 403 | `FORBIDDEN` | 원무가 아님 |
| 404 | `NOT_FOUND` | 없는 결제번호 |
| 409 | `INVALID_STATUS` | 상태가 '완료'가 아님. '미결제'는 취소할 수 없고(상태 순서), 이미 '취소'된 결제를 다시 취소하려는 경우도 여기 해당. S6b는 새로 생긴 미결제 건으로 안내 |

**규칙**

- 취소한 결제는 지우지 않고 '취소'로 보관합니다. 결제수단과 결제일시는 원래 값을 그대로 둡니다('취소'도 CHECK로 필수).
- 함수형 UNIQUE: 진료마다 '취소'가 아닌 결제는 1건입니다.
- 입원 청구를 취소하면 새 결제도 입원 산식으로 다시 계산합니다.
- 업무분담서 완료 기준: 수납 후 취소하면 기존 취소 건과 새 미결제 건이 각각 1건씩 남습니다.

**백엔드 메모**

- 반드시 **기존 결제를 '취소'로 바꾼 다음** 새 결제를 INSERT 합니다. 순서를 바꾸면 '취소'가 아닌 결제가 잠깐 2건이 되어 함수형 UNIQUE에 걸립니다.
